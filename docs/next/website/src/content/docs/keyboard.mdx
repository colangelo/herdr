Herdr is mouse-native. You can click panes, tabs, workspaces, and agents, drag split borders, and use right-click menus without learning a single keybinding. Keyboard control is optional.

## What the prefix is

A terminal multiplexer sits between your terminal and the programs running inside it. Those programs already use most key combinations: `ctrl+c` interrupts, `ctrl+r` searches history, editors claim nearly everything else. If Herdr grabbed common keys directly, it would break the programs inside it.

The prefix solves this. Press the prefix key, default `ctrl+b`, and the next keypress goes to Herdr instead of your terminal. `prefix+c` means: press `ctrl+b`, release, then press `c`. Herdr reserves one key instead of dozens.

Press `prefix+?` at any time to see every active binding. Press `/` in the keybind help to filter actions and shortcuts; use Backspace to edit the filter or `ctrl+u` to clear it.

## Learn these five first

| Action | Key |
| --- | --- |
| New tab | `prefix+c` |
| Split right / down | `prefix+v` / `prefix+minus` |
| Move between panes | `prefix+h/j/k/l` |
| Workspace navigation | `prefix+w` |
| Detach, leave everything running | `prefix+q` |

These cover most daily movement. Everything else can stay on the mouse.

## The rest, by task

Panes:

| Action | Key |
| --- | --- |
| Zoom the focused pane | `prefix+z` |
| Close pane | `prefix+x` |
| Break pane into a new tab | `prefix+!` |
| Move pane to a chosen tab or space | `prefix+m` |
| Move pane to next / previous tab | `prefix+>` / `prefix+<` |
| Swap panes | `prefix+shift+h/j/k/l` |
| Resize mode | `prefix+r` |
| Balance panes (equal sizes) | `prefix+=` |
| Cycle layout preset (even-h → even-v → tiled) | `prefix+space` |
| Copy mode | `prefix+[` |
| Copy mode, scrolled up a page / half page / line | `prefix+PageUp` / `prefix+ctrl+u` / `prefix+ctrl+k` |
| Pane todos | `prefix+ctrl+t` |
| Add a pane todo | unset |

Tabs:

| Action | Key |
| --- | --- |
| Next / previous tab | `prefix+n` / `prefix+p` |
| Jump to tab 1–9 | `prefix+1..9` |
| Rename tab | `prefix+shift+t` |
| Close tab | `prefix+shift+x` |

Pane moves preserve the pane's running process and terminal contents. `prefix+m` opens a destination picker listing every place the pane can go: the other tabs of its own space, the tabs of every other space, a new tab in any of them, and a new space created by the move. Destinations are grouped under their space, with the pane's own space first; the space headings are labels, not destinations, so the selection steps over them. Picking a destination in another space switches to that space with the moved pane focused. The quick next/previous actions stay within the current space, follow the current tab order and stop at the first or last tab instead of wrapping. Pane moves are unavailable when the source or destination tab is zoomed.

Workspaces and session:

| Action | Key |
| --- | --- |
| New workspace | `prefix+shift+n` |
| Rename workspace | `prefix+shift+w` |
| Close workspace | `prefix+shift+d` |
| Goto picker | `prefix+g` |
| Toggle sidebar | `prefix+b` |
| Notification center | `prefix+ctrl+n` |
| Jump to the current toast's pane | `prefix+o` |

The notification center (`prefix+ctrl+n`, or click the `◆` indicator at the top right of the tab bar) lists recent notifications newest-first. Unread entries show a kind-colored dot and a bold title; the `◆` unread count only goes down as you visit them — opening the panel changes nothing. With `ui.notification_center_position = "bottom-right"` the indicator floats in the frame's bottom-right corner instead, and the panel opens above it. Inside it, `Up`/`Down` or `j`/`k` move the selection, `Enter` jumps to the selected notification's pane, marks it read, and closes, `Esc` or `q` closes, and clicking a row does the same as `Enter` for that row. `r` (or the "mark read" button) marks everything read while keeping the history; `c` (or the "clear all" button) empties the log. Notifications without a pane target are not actionable and stay unread.

Every pane that draws a top border carries a `▾` indicator at the right end of it. A pane with outstanding todos shows their count, coloured by the highest priority among them; a pane whose todos are all done shows a bare `▾`; a pane with no todos shows the same `▾` dimmed further still, so the control is in the same place on every pane and an empty pane can be opened by mouse. A pane drawing no top border — a single-pane tab, or `ui.pane_borders = false` — has nowhere to put it, and the keybinding is the route there.

`prefix+ctrl+t`, or a click on the indicator, opens that pane's todo panel. Inside it, `Up`/`Down` or `j`/`k` move the selection, `a` adds a todo, `Enter` (or a row click) opens the todo for editing, `Space` toggles done, `g` (or the footer's `go` button, or a click on the link chip) follows a linked todo to its pane, `d` removes the selected todo, `c` clears the completed ones, and `Esc` or `q` closes. The `go` button appears only while the selected todo's link still resolves, since a dead link is inert. The add action is offered even when the pane holds no todos. A todo linked to a pane that no longer exists renders dimmed and does nothing when followed.

In the edit view, `Tab` cycles the priority, `ctrl+l` opens the link picker, `ctrl+t` toggles done (the panel's `Space`, which the edit view's text field owns), `ctrl+s` saves, `ctrl+g` saves and then follows the link, and `Esc` cancels. Terminals that report the enhanced keyboard protocol can save with `alt+Enter` too. Clicking the priority, link, or done row does the same as its shortcut. The done row is absent while composing a new todo, which is never already done. `keys.add_pane_todo` is unset by default and opens the edit view on a new todo. Set `ui.show_pane_todo_indicator = false` to hide the indicator, and `ui.pane_todo_color` to override its color.

The text field has an insertion point, so typing and pasting land where the cursor is rather than at the end, and a click in the text puts the cursor there. The readline chords all work:

| Action | Keys |
| --- | --- |
| Line start / end | `ctrl+a` / `ctrl+e` |
| Character back / forward | `ctrl+b` / `ctrl+f`, `Left` / `Right` |
| Word back / forward | `alt+b` / `alt+f`, `ctrl+Left` / `ctrl+Right` |
| Line up / down | `Up` / `Down` |
| Delete backward / forward | `Backspace` / `ctrl+d`, `Delete` |
| Kill to line end / start | `ctrl+k` / `ctrl+u` |
| Kill the word behind the cursor | `ctrl+w`, `alt+Backspace` |
| Yank the last kill | `ctrl+y` |
| Undo | `ctrl+_`, `ctrl+-`, `ctrl+/` |

The kill ring is Herdr's own and holds one entry; `ctrl+y` puts back what `ctrl+k`, `ctrl+u`, or `ctrl+w` last took, and has nothing to do with the system clipboard. System paste stays on the usual paste chord, and now keeps the newlines in what you paste while still dropping other control characters.

A todo can hold more than one line: `Enter` inserts a newline. That is why `Enter` no longer saves and `ctrl+d` no longer toggles done — the field needs both. The edit view shows three lines at a time and scrolls to follow the cursor. In the panel, a multi-line todo still occupies one row, showing its first line with a `⏎` marker.

The link picker is the session navigator in a selection mode: it lists every pane in every workspace, searchable and filterable, named the way the navigator names them, so a pane running a plain shell is identified by the command it launched. Each pane row shows the public pane identifier it would stage, like `w2:pC`. Choosing a pane row stages it as the target; a `no link` entry at the top clears the link instead. Workspace and tab rows are context only — activating a workspace expands or collapses it, and neither ends the selection. The todo's own pane is not offered. `Esc` leaves the picker with the link exactly as it was.

`ctrl+j` and `ctrl+k` move the selection anywhere in the picker, including while its search is focused, alongside the arrow keys and `ctrl+n`/`ctrl+p`. The same chords work in the ordinary goto picker (`prefix+g`), which is the same surface.

A live link is shown as `→ w2:pC · claude` — the pane's public identifier first, because that is the part you can act on with `herdr pane`, `herdr agent read`, or a sibling agent's prompt, and the captured label after it, because that is the part you recognise. The identifier is resolved from the live target every time it is drawn, so it follows a pane that moves. A dead link has no identifier to show and keeps its label alone.

`ctrl+g` in the edit view is `ctrl+s` then `g` in one keystroke: it commits what you typed and moves focus to the linked pane. The link row shows a `^g go` hint whenever it has somewhere to go — including a target staged in the picker but not yet saved. With no link, a cleared one, or a target that has gone, the chord is inert and saves nothing either, so it never commits an edit and then fails to travel. A save the store refuses (empty text, over the cap) leaves the modal open with the reason on screen rather than travelling away from it.

Closing a pane that still has outstanding todos asks for confirmation first; a pane whose todos are all done closes without a prompt.

The full keymap and the binding syntax live in the [keybinding reference](/docs/configuration/#keybindings).

## Copy mode

Press `prefix+[` to enter copy mode for the focused pane. You can also enter it in one gesture, already scrolled up: `prefix+PageUp` (page), `prefix+ctrl+u` (half page), or `prefix+ctrl+k` (one line), like tmux `copy-mode -u`; repeating a gesture scrolls further, and leaving copy mode still restores the position from before the first gesture. (With a prefix other than the default `ctrl+b`, you can bind `keys.copy_mode_page_up` to `prefix+ctrl+b` too; with the default prefix that chord stays send-prefix.) Use `h/j/k/l`, tmux-style `w/b/e` and big-word `W/B/E`, `{`/`}`, `PageUp`/`PageDown`, `ctrl+b`/`ctrl+f`, and `ctrl+u`/`ctrl+d` to move, and `ctrl+k`/`ctrl+j` to scroll the viewport one line up or down without moving the cursor relative to the text (vim `ctrl+y`/`ctrl+e`). Held motions repeat: keeping `ctrl+u`/`ctrl+d` or `ctrl+k`/`ctrl+j` pressed keeps scrolling. Press `/` or `?` for forward or backward literal search, then `n` or `N` to repeat in the same or opposite direction. Search is case-insensitive unless the query contains an uppercase letter. Use `v` or Space to start a selection, `y` or Enter to copy it, and `q` or Esc to leave without copying. Esc clears an active selection or search before exiting. Copy mode does not pause the pane process: output remains live, follows at the bottom, and stays pinned when you navigate into history. The configured prefix keeps its normal meaning in copy mode; with the default prefix, `ctrl+b` enters prefix mode instead of paging up, so use a different prefix if you want `ctrl+b` for copy-mode page-up. Mouse drag-select copies without entering copy mode at all.

### Scrolling fullscreen apps

A fullscreen application — one that owns the alternate screen, like `vim`, `htop`, or Claude Code's fullscreen renderer — keeps the pane's scrollback empty and scrolls itself, so there is no history for copy mode to enter. On such a pane the scroll gestures (`prefix+PageUp`, `prefix+ctrl+u`, `prefix+ctrl+k`) switch to a scroll passthrough mode instead: Herdr forwards paging keys to the app so you can keep scrolling from the home row. `ctrl+u`/`ctrl+d` (or `PageUp`/`PageDown`) page up and down, `ctrl+k`/`ctrl+j` (also `k`/`j` or the arrow keys) scroll a few lines at a time, `g`/`G` (or `Home`/`End`) jump to the top or bottom, and `q`, Esc, or Enter return your keys to the app. Line scrolling rides on synthesized wheel events — Herdr encodes them exactly like a physical wheel over the pane, so the arrows never type into the app's prompt history. A `SCROLL` bar at the bottom shows while the mode is active. Plain `prefix+[` still enters ordinary copy mode over the visible screen, for selecting text with the keyboard.

## Change anything

Every binding is configurable, including the prefix itself:

```toml
[keys]
prefix = "ctrl+a"
```

## Going prefix-free

You can bind Herdr actions to direct chords that need no prefix at all. The hard part is knowing which chords are safe, because terminals, shells, and desktop environments already own most of the keyboard.

Any chord works as a binding: `ctrl+j`, `alt+k`, whatever fits your hands. But a chord has to survive three layers before Herdr sees it: your operating system, your outer terminal (Ghostty, iTerm2, and others ship their own defaults), and the programs running inside the pane. `ctrl+j` reaches Herdr fine, but shells and editors treat it as enter. `alt+k` is free on Linux, but macOS composes it into a special character in most terminals. If you pick chords from these families, double-check them against your own terminal and OS shortcuts.

On macOS specifically, `alt+e`, `alt+i`, `alt+n`, and `alt+u` are worth avoiding entirely. On ABC and most Latin layouts those are Option dead keys for combining accents: Option+e emits `´`, and Option+i emits nothing at all while it waits for a letter to accent. Neither arrives as `alt+e` or `alt+i`, so Herdr cannot bind them. Setting Ghostty's `macos-option-as-alt` does not help — it changes how plain Option is translated, not dead-key composition, so `alt+d` gets through while `alt+e` still does not. Indexed jump ranges skip these four letters on macOS for exactly this reason (see [indexed jumps](/docs/configuration/#indexed-jumps)).

We mapped the default keybindings of Ghostty, iTerm2, Terminal.app, kitty, WezTerm, Alacritty, Warp, Windows Terminal, GNOME Terminal, and Konsole, plus the global shortcuts of GNOME and KDE. One modifier family is almost untouched everywhere: `ctrl+alt`. Terminals leave it free, it is not affected by the macOS option-key composing behavior that blocks plain `alt` chords, and it transmits even in terminals without a modern keyboard protocol. It is a safe default, but the choice is yours.

This setup keeps the prefix bindings working and adds direct chords on top:

```toml
[keys]
focus_pane_left = ["prefix+h", "ctrl+alt+h"]
focus_pane_down = ["prefix+j", "ctrl+alt+j"]
focus_pane_up = ["prefix+k", "ctrl+alt+k"]
focus_pane_right = ["prefix+l", "ctrl+alt+l"]
previous_tab = ["prefix+p", "ctrl+alt+["]
next_tab = ["prefix+n", "ctrl+alt+]"]
new_tab = ["prefix+c", "ctrl+alt+c"]
split_vertical = ["prefix+v", "ctrl+alt+d"]
split_horizontal = ["prefix+minus", "ctrl+alt+shift+d"]
zoom = ["prefix+z", "ctrl+alt+z"]
```

A few `ctrl+alt` chords are taken elsewhere. Avoid these:

| Chord | Owned by |
| --- | --- |
| `ctrl+alt+arrows` | GNOME workspace switching, Ghostty and Konsole defaults |
| `ctrl+alt+t` | "Launch terminal" on Ubuntu and Fedora |
| `ctrl+alt+l` / `ctrl+alt+a` | KDE lock screen / attention window |
| `ctrl+alt+s` / `ctrl+alt+u` | Konsole |
| `ctrl+alt+f1..f12` | Linux virtual console switching |

If a direct chord does nothing, your terminal or desktop environment consumed it before Herdr could see it. Rebind either side: free the chord in the terminal's settings, or pick another chord in Herdr.
